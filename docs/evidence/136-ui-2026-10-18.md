## Real staging browser boundary

Separately, an ephemeral Chromium context used a **real fresh Google ID/access
token set** from established test consent against live staging. No interactive
Google consent/sign-in flow was exercised. No API response was replaced or stubbed.
All non-GET/HEAD/OPTIONS requests were blocked defensively; **zero financial
mutations were attempted**. API `/warm`, Bank, suggestions and desktop history
returned 200 through native browser CORS.

Both viewports verified initial All/collapsed state, the real retained Transaction,
three initial candidates, Show more revealing five after the eighth Expense was
retained, one expanded row and exact `No suggested matches` wording. Live Save,
Match/Unmatch controls and return-context are not proved by this read-only run;
those behaviors have separate local stubbed evidence above. The static desktop
footer still says `Stubbed data · No Live API Connection` despite real successful
API calls (`src/app/features/shell/components/shell.html:92`); it is not a reliable
runtime provenance indicator.
